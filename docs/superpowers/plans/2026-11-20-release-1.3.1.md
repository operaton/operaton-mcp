# Release 1.3.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix #113 (multipart deploy) and #114 (request bodies not modelled), enable patch releases from `release/X.Y.x`, ship via PRs and a dry-run release.

**Architecture:** Multipart client separates text fields from file parts. Generator converts OpenAPI request-body JSON Schema into inline Zod source per operation and merges it with path/query params. Release workflow branches on `GITHUB_REF_NAME`.

**Tech Stack:** TypeScript (ESM), Zod 4, vitest, msw, GitHub Actions, JReleaser, Docker (`operaton/operaton`).

**Spec:** `docs/superpowers/specs/2026-11-20-release-1.3.1-design.md`

## Global Constraints

- Branches: `release/1.3.x` from `v1.3.0`; feature branch `fix/1.3.1-deploy-and-request-bodies`; forward-port branch `fix/forward-port-1.3.1` from `main`.
- Version `1.3.1-SNAPSHOT` on `release/1.3.x` in its own commit `chore: set version 1.3.1-SNAPSHOT`; no other commit touches `version`.
- One commit per concern (#113, #114, workflow, deps, docs); Conventional Commits; commitlint must pass.
- Every new `.ts` file carries the Apache license header (`npm run check:license`).
- `src/generated/` is gitignored — only `scripts/generate.ts` changes are committed.
- No `$ref`/`$defs` in tool `inputSchema`; no `JSON.parse` coercion in handlers.
- Inline `$ref` depth limit 4; cycle or deeper → `z.unknown()`.

## Review Focus

1. `$ref` cycles in component schemas (e.g. self-referencing query DTOs) → generator terminates, emits `z.unknown()` at the cycle. Test in Task 3.
2. Body field named like path param (`id` in `updateTask`, `updateProfile`) → path value used in URL, body copy not declared twice, schema still valid. Test in Task 3.
3. Query params on body operations must not leak into the JSON body (current code sends them). Test in Task 3.
4. DMN with non-default filename and BPMN without filename → part filename is the given/default name ending in `.dmn`/`.bpmn`. Test in Task 2.
5. Non-object body (array or untyped schema) → exposed as `body` field, sent as-is. Test in Task 3.

### Task 3: #114 generator request bodies

**Files:**
- Modify: `scripts/generate.ts`
- Test: new `test/unit/generated/request-body.test.ts`

**Interfaces:**
- Produces (in `scripts/generate.ts`, exported for test only if needed):
  ```ts
  interface SpecOperation { path; method; parameters; requestBodySchema?: JsonSchema }
  function jsonSchemaToZod(schema: JsonSchema, components: Record<string, JsonSchema>, seen: Set<string>, depth: number): string
  ```
- Generated handler contract: path/query params read from `validated`; body = object of all input keys except path/query param names (declared body props + passthrough extras); non-object body → `validated.body`.

- [ ] **Step 1: Failing test** `request-body.test.ts` (runs generator in `beforeAll` like `generation.test.ts`):
  - `every exposed tool declares its request body properties`: for each spec op with `application/json` object body and manifest `expose: true`, import `src/generated/<group>/<opId>.js`, `z.toJSONSchema(schema, { target: "draft-7", io: "input" })`; expect `Object.keys(props)` ⊇ body props (minus path/query collisions).
  - `decision_evaluate types variables as object map`: `properties.variables.type === "object"`, `additionalProperties.properties.value` exists.
  - `no $ref in any generated tool schema`: `JSON.stringify(jsonSchema)` does not contain `"$ref"`.
  - `updateTask keeps id as required path string`: `properties.id.type === "string"`, `required` contains `id`.
  - `body excludes path and query params`: call `evaluateDecisionByKey({ key: "k", variables: { a: { value: 1, type: "Integer" } } }, mockClient)`; assert `post` called with ``/decision-definition/key/k/evaluate`` and body `{ variables: {...} }` (no `key`). Pick one exposed POST op with a query param and assert the query param is absent from body.
  - `array body exposed as body field`: pick an exposed op whose body schema is `type: array` (find via spec; skip with note if none exposed) → schema has `body` property, client receives the array.
  - `cyclic schema terminates`: unit-call `jsonSchemaToZod` with `{ A: { type: object, properties: { a: { $ref: "#/components/schemas/A" } } } }` → output contains `z.unknown()`.
- [ ] **Step 2:** `npx vitest run test/unit/generated/request-body.test.ts` → FAIL.
- [ ] **Step 3: Implement.** `parseSpec` stores `requestBody.content["application/json"].schema` and `components.schemas`. `jsonSchemaToZod` maps: object→`z.object({...})` (non-required `.optional()`, `additionalProperties` schema → `z.record(z.string(), X)` when no properties), array→`z.array(X)`, string (+`enum` → `z.enum([...])`), integer/number→`z.number()`, boolean, `nullable`→`.nullable()`, `oneOf/anyOf/allOf`→`z.unknown()` unless trivial; `description` → `.describe(JSON.stringify(desc))`. Top-level body props merged into the input object after params (skip names colliding with params); body props always `.optional()` at top level unless in the body's `required`. Keep `.passthrough()` for object bodies. Replace the existing `bodyBlock` with destructuring of all path+query param names.
- [ ] **Step 4:** Test → PASS; `npm run build && npm test` → all pass (existing tests may need updated expectations where bodies previously included query params).
